# 饥荒联机版（DST）一键开服教程

本教程面向使用 Game Server Hub 面板开服的服主，覆盖从准备服务器到朋友进服的完整流程。安装、升级、回滚与运维排错见 [安装与运维指南](INSTALL.md)；本文专注于"把服务器开起来、管起来"。

---

## 快速答案

| 问题 | 结论 |
| --- | --- |
| 安全组要开放哪些端口？ | 面板 9527/tcp；主世界 10999/udp、8766/udp、12346/udp；**开启洞穴再加** 11000/udp、8768/udp、12348/udp |
| 面板默认对外访问地址？ | http://<服务器公网 IP>:9527。安装器会自动解析并打印（显式 `PANEL_PUBLIC_URL`/`PANEL_HOST` → 网卡公网地址 → 云平台元数据 → 出站 IP 探测 → 本机地址）；NAT 机器上探测不到时会打印本机内网地址并提示公网访问怎么做 |
| 需要配置 IP 转发吗？ | **不需要**。Docker 模式由 Docker 自动完成端口映射，Native 模式进程直接监听宿主机端口 |
| 宿主机在 NAT 后面要额外加转发规则吗？ | **要**（云平台端口转发 / 路由器映射）：主世界 3 个 + 洞穴 3 个 UDP 各一条，外部端口与内部一致，见 5.4 节 |
| 主世界/洞穴端口要手动开放吗？ | **要**。面板和安装器默认不碰云安全组，主世界与洞穴的全部 UDP 端口都需手动放行 |

## 1. 认识面板

Game Server Hub 是一个开源的游戏服务器运维面板，当前完整适配《饥荒联机版》（DST），提供：

- 实例创建、SteamCMD 安装/更新、启动、停止和重启
- 地上/洞穴双分片、房间、世界生成和 Mod 管理
- 主机与实例 CPU、内存、磁盘、网络监控
- SSE 实时日志、游戏控制台命令
- 存档备份与恢复、计划任务
- Docker Compose 与 Native systemd 双运行时

**两种部署模式怎么选：**

| 模式 | 适合谁 | 运行方式 |
| --- | --- | --- |
| Docker | 小型社区、托管商 | 面板与游戏均为 Docker 容器 |
| Native systemd | 个人服主 | 面板为系统服务，游戏进程由 gsh 用户的 systemd 服务管理 |

两种模式的面板功能完全一致，教程内容通用；涉及差异处会单独标注。

## 2. 准备工作

### 2.1 服务器要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Ubuntu 22.04 / 24.04 或 Debian 12 |
| 内存 | 最低 4 GiB；**开洞穴**推荐 6 GiB；大量 Mod 推荐 8 GiB+（见 [内存建议](MEMORY.md)） |
| 磁盘 | 根分区至少 4 GiB 空闲；另需为镜像（离线包约 227 MB，导入后本地镜像约 560 MB）、游戏本体（数 GB）、存档与备份预留空间 |
| 权限 | root 或 sudo |
| 网络 | HTTPS 出站（下载脚本、镜像与游戏） |

只支持 apt 系发行版，不支持 CentOS/RHEL/Alpine。建议选择与玩家距离近的机房（影响联机延迟）。

### 2.2 获取 Klei 集群令牌（公网联机必须）

玩家要能从游戏内"浏览游戏"列表找到你的服务器，必须配置 Klei 集群令牌（pds- 开头）：

1. 打开 <https://accounts.klei.com/>，用 Steam 账号登录；
2. 进入 **Games（游戏）→ Don't Starve Together Servers**；
3. 点击 **Add New Server（添加新服务器）**，填写一个集群名称；
4. 复制生成的集群令牌（以 pds- 开头的长字符串），后面"创建房间"时要用。

> 只玩离线/局域网可以跳过这一步，但从联机列表进人是必须配令牌的。

## 3. 下载脚本并安装

### 3.1 一键安装命令

SSH 登录服务器后，按部署模式选择一条命令执行。

**Docker 模式**（推荐托管与社区使用）：

> 中国大陆服务器请**先导入离线镜像包，再跑这条命令**。安装器要从 GHCR 拉取统一镜像，而 GHCR 的镜像层域名在国内基本不可达，直接跑几乎必然失败（`TLS handshake timeout`）。离线包步骤见 [INSTALL.md · 离线镜像包完整步骤](INSTALL.md#路线-b国内服务器debian-12-离线镜像包全程)。

```bash
curl -fsSL https://raw.githubusercontent.com/PMAT77/game-serve-hub/v0.10.0/scripts/install.linux.sh \
  | sudo bash -s -- --mode docker
```

**Native systemd 模式**（个人服主常用，不依赖 Docker；选型见 [INSTALL.md · 两种模式怎么选](INSTALL.md#两种模式怎么选)）：

```bash
curl -fsSL https://raw.githubusercontent.com/PMAT77/game-serve-hub/v0.10.0/scripts/install.linux.sh \
  | sudo bash -s -- --mode native
```

**国内网络**（GitHub Raw 不稳定时，换 jsDelivr 源并启用国内档位；下面的 `--mode` 按你要装的模式替换）：

```bash
curl -fsSL https://cdn.jsdelivr.net/gh/PMAT77/game-serve-hub@v0.10.0/scripts/install.linux.sh \
  | sudo bash -s -- --mode native --network cn
```

Docker 在国内还要先导入离线镜像包，完整步骤见 [INSTALL.md · 路线 B](INSTALL.md#路线-b国内服务器debian-12-离线镜像包全程)；Native 在国内的完整步骤与加速代理回退见 [INSTALL.md · 路线 D](INSTALL.md#路线-dnative-国内服务器加速代理与国内档位)。

建议**明确指定 --mode**，避免自动判断与你的预期不一致。

> 三条命令都是管道下载，锁定当次内容、不会误用磁盘上的旧脚本。安装版本由脚本第 9 行的默认 tag 决定，想先确认可执行
> `curl -fsSL "<上面的 URL>" | sed -n '9p'`，应输出 `...:-v0.10.0}}`。
> 这个 tag 必须与本地镜像 tag 一致：用离线包导入过镜像时，两边对不上，安装器仍会重新拉取。

### 3.2 安装参数

| 参数 | 说明 |
| --- | --- |
| --mode auto\|docker\|native | 部署模式；管道安装时 auto 默认选 Docker |
| --network auto\|cn\|global | 网络档位；cn 临时切换国内软件源、提高 SteamCMD 重试，失败自动还原 |
| --open-panel-port | 安装时在本机防火墙（ufw/firewalld）放行面板 9527/tcp |
| --open-dst-ports | 安装时在本机防火墙放行 DST 游戏端口 |

> 安装器默认**不修改任何防火墙**。加了 --open-* 参数也只影响本机防火墙，云厂商安全组永远需要你手动放行（见第 4 章）。

### 3.3 安装器做了什么

- 检查系统、磁盘、端口与网络连通性；
- **Docker**：安装 Docker 与 Compose，下载 Compose 文件，生成 panel.env，拉取统一镜像（面板 + DST 运行库 + SteamCMD 三合一）并启动；
- **Native**：安装 SteamCMD 及 i386 运行库，创建 gsh 系统用户，下载校验 Native Release，注册 game-server-hub.service 并启动；
- 解析面板访问地址并按来源标注：显式 `PANEL_PUBLIC_URL`/`PANEL_HOST` → 网卡公网地址 → 云平台元数据 → 出站 IP 探测 → 本机地址，结果写进 `/opt/game-server-hub/panel.env` 的 `PANEL_PUBLIC_URL`（面板自身不读这个值，它只是记录，改域名/反代直接编辑该行即可）；
- 生成随机初始密码写入权限受限的 /opt/game-server-hub/panel.env，安装摘要给出访问地址。

安装完成后先验证健康状态：

```bash
curl -fsS http://127.0.0.1:9527/health
```

返回 JSON 中 runtime.status 为 running 即正常。安装失败时看 /var/log/game-server-hub/install.status 与 install.diagnostics.log。

## 4. 开放端口：安全组与防火墙

### 4.1 需要开放的端口清单

| 用途 | 协议 | 默认端口 | 何时需要 |
| --- | --- | --- | --- |
| 面板 Web | TCP | 9527 | 始终需要 |
| 主世界 · 游戏端口 | UDP | 10999 | 始终需要 |
| 主世界 · Steam 认证端口 | UDP | 8766 | 始终需要 |
| 主世界 · Steam 主服端口 | UDP | 12346 | 始终需要 |
| 洞穴 · 游戏端口 | UDP | 11000 | 开启洞穴时需要 |
| 洞穴 · Steam 认证端口 | UDP | 8768 | 开启洞穴时需要 |
| 洞穴 · Steam 主服端口 | UDP | 12348 | 开启洞穴时需要 |

> 如果你后来在世界设置里改过某个分片的端口，安全组要按新端口同步放行（改游戏端口后 Steam 端口不会自动跟随，需一并调整）。

> 上表是**宿主机**层面要放行的端口：容器内部端口由 Docker 一比一发布到宿主机（10999→10999），Docker 自己维护这条映射，不需要你写转发规则。若宿主服务器本身在 NAT 转发（云平台端口映射 / 路由器映射）后面，安全组之外还要逐条添加转发规则，见 5.4 节。

### 4.2 云安全组操作

主流云厂商（阿里云、腾讯云、AWS 等）都默认拒绝入站流量，需要手动添加放行规则：

1. 登录云控制台，找到服务器的 **安全组 / 防火墙** 配置页；
2. 添加入站规则：
   - 允许 **TCP 9527**（来源 0.0.0.0/0，或仅填你自己的 IP 更安全）；
   - 允许 **UDP 10999、8766、12346**（来源 0.0.0.0/0）；
   - 开洞穴的再加 **UDP 11000、8768、12348**；
3. 保存规则后无需重启服务器。

游戏 UDP 端口必须对全网开放，玩家才能连接；面板 TCP 端口建议只对你自己的常用 IP 开放。

### 4.3 本机防火墙

- 服务器开了 ufw/firewalld 时，可以用安装参数 --open-panel-port 与 --open-dst-ports 自动放行；
- 也可以手动放行，例如 sudo ufw allow 9527/tcp、sudo ufw allow 10999/udp；
- 没开本机防火墙的（多数云主机默认状态）只需配置安全组即可。

## 5. 需要配置 IP 转发吗？

分场景回答，不要一概而论。

### 5.1 云服务器 / 独立 Linux 主机：不需要

- **Docker 模式**：面板容器通过端口映射发布 9527；游戏分片容器由面板动态创建，端口一比一绑定到宿主机（10999→10999），Docker 自动维护 NAT 规则，无需你开启内核 ip_forward 或写任何转发规则；
- **Native 模式**：游戏进程直接监听宿主机端口，连容器都没有。

也不需要 frp、nps 之类的内网穿透工具——那是家用电脑开服的方案，云服务器直接放行安全组即可。

### 5.2 Windows 开发环境：只保证本机进服

**Windows 不是部署目标。** 它只用于本机开发调试——本项目不提供 Windows 安装脚本，也不为"让他人联机"做兼容（原因见本节末尾）。

开发场景下只需保证一件事：**游戏客户端（与面板同一台电脑）能用「本机」档进服**。这类环境下游戏端口绑定在 **WSL 的网络命名空间**里，不由 Windows 直接监听，第 4 章的"放行安全组"说明不适用：

| 运行方式 | 本机进服 `c_connect("127.0.0.1", …)` |
| --- | --- |
| Rancher Desktop / Docker Desktop | 宿主侧自带 Windows↔WSL 端口转发（含 UDP），可用 |
| WSL 内原生 Docker（默认 NAT 模式） | 不保证可用；改用 WSL 的 IP（WSL 里执行 `hostname -I`） |

配合控制台的直连命令使用时注意：

- **本机游玩请用「本机」档。** 面板跑在容器里时看不到宿主机网卡，「局域网」档通常为空；「公网」档来自出站 IP 探测，只表示"这条线路的出口"，在家用 NAT / 容器 / 系统代理环境下往往无法直连（开着代理时甚至可能返回代理出口地址）。面板已按地址来源自动选择默认档位，显示不对可用命令框右侧按钮切换。
- **不要为了让他人联机去折腾 Windows 侧网络。** 容器运行时会额外引入一层网络边界（典型如 Rancher Desktop 只把端口绑到 `127.0.0.1`），让端口暴露成倍复杂而收益很低。需要长期开服给他人玩，请用 Linux 服务器或云主机（见 5.1），那才是本项目的目标场景。
- 需要固定覆盖进服地址时，在 `panel.env` 设置 `GSH_DST_CONNECT_HOST`（并用 `GSH_DST_AUTO_PUBLIC_IP=0` 关闭出站探测），见 [`panel.env.example`](../panel.env.example)。

> Windows 不作为部署目标的原因：桌面 Windows 会休眠、会自动更新重启，无法承担长期在线的游戏服务器；Klei 官方同样建议独立服务器搭在 Linux 上而非 Windows 上。生产部署见 [INSTALL.md](INSTALL.md)。

### 5.3 家庭宽带 / 二级路由 NAT：需要端口映射

如果你的服务器在家庭宽带或二级路由 NAT 后面（没有公网 IPv4），需要在路由器上把 4.1 的端口映射到服务器内网 IP，此时才属于"端口转发"范畴。光猫若也是路由模式，还需在光猫上再做一层映射。

映射前先确认运营商给的是**真公网 IPv4**：对比路由器 WAN 口 IP 与服务器上 `curl -s --noproxy '*' https://api.ipify.org` 的结果，一致才是真公网。若服务器出口 IP 与路由器 WAN 口对不上、且 WAN 口是 `10.` / `100.64.` / `172.16-31.` 开头，说明上游还有一层 NAT（CGNAT），端口映射不会生效，只能改用内网穿透方案。

### 5.4 宿主服务器在 NAT 转发后面

本节针对宿主本身在 NAT 后面的场景：云平台的「端口转发 / NAT 映射」（云电脑、轻量应用、NAT 网关型实例）或路由器端口映射 —— 公网 IP 不在宿主网卡上，**只放行安全组是不够的**。

先把三层分清，别把它们混为一谈：

| 层次 | 谁负责 | 主世界（Master） | 洞穴（Caves） | 面板 |
| --- | --- | --- | --- | --- |
| 容器内进程监听 | 面板启动的游戏进程 | UDP 10999 / 8766 / 12346 | UDP 11000 / 8768 / 12348 | TCP 8888 |
| 宿主机端口发布 | **Docker 自动**（一比一） | 同端口 UDP | 同端口 UDP | PANEL_PORT（安装默认 9527） |
| 宿主机防火墙 + 云安全组 | 你 | 3 个 UDP | 3 个 UDP | TCP 9527 |
| 平台 NAT / 路由器端口转发 | 你（仅当宿主无直连公网 IP 时） | 3 个 UDP | 3 个 UDP | TCP 9527 |

**判断要不要加转发规则：**

- **宿主有直连公网 IP**（普通云主机 EIP、直挂公网）：**不需要任何转发规则**。Docker 的端口发布本身就是宿主机上的 DNAT，由 Docker 自己维护；你只需配安全组与本机防火墙，也不用开内核 `ip_forward`、不用写 iptables、更不用 frp/nps。
- **宿主在 NAT 后面**：**要**，且必须满足三条：
  1. 主世界 3 个 + 洞穴 3 个 UDP **每个都要一条规则**。只映射 10999 是最常见的漏配，表现为能进主世界、一进洞穴就崩线；
  2. 面板 TCP 也要一条，目标端口写**宿主机的面板端口**（生产安装默认 9527），不是容器内部的 8888；
  3. **外部端口必须等于内部端口**（10999→10999、11000→11000 …）。DST 会把自己 `server.ini` 里的 `server_port` 上报给 Klei/Steam，玩家从列表进服、以及从主世界切进洞穴都按上报端口连接；公网端口被平台改成随机高位，就会出现「列表里搜得到、点不进去」。
- 平台只给随机高位端口、且不允许自定义时：把该实例的分片端口改成平台分配的公网端口号（面板「世界设置 → 网络」），让内外一致；否则只能接受直连 `c_connect("<公网IP>", <公网端口>)`，从 Klei 列表进服不可用。

**不需要开放的端口：** 分片之间通信用的是 `10888`。Docker 模式下洞穴的 `cluster.ini` 里 `master_ip` 写的是主世界容器的**容器名**，两个分片走实例专用 bridge 网络 `gsh-net-<实例 ID>` 互联，不经过宿主机端口，对外放行它没有意义。

**验证：**

```bash
# 1) 宿主机上应看到 6 条 UDP 发布 + 面板 TCP
docker ps --format '{{.Names}}\t{{.Ports}}'

# 2) 从另一条网络（例如手机流量）逐端口探测
nc -vzu <公网IP> 10999
nc -vzu <公网IP> 11000
```

在服务器**内部** `curl` 自己的公网 IP 会得到 `Connection refused` —— 这是 NAT 不支持回环的正常现象，不代表配置有错（见 6.1）。

## 6. 首次登录与修改密码

### 6.1 访问面板

浏览器打开安装摘要给出的地址，默认格式：

```text
http://<服务器公网 IP>:9527
```

例如 http://123.45.67.89:9527。如果打不开，按顺序检查：安装是否完成（/health）、安全组是否放行 9527/tcp、浏览器与服务器之间的网络。

**云平台 NAT 转发模式**：部分云主机（尤其「云电脑」、轻量应用等产品）的公网 IP 并不与机器直连，端口需要在控制台的「**端口转发 / NAT 映射**」里显式配置。此时：

- **只放行安全组是不够的**，必须在这里有转发规则，否则外部完全连不上（表现为超时，而不是连接被拒绝）；
- 面板要映射的是**宿主机的面板端口**（生产安装默认 `9527`），不是容器内部的 `8888`；公网端口若被平台改成随机高位（例如公网 `203.0.113.10:13992`），浏览器就用公网端口访问。

另外两点容易踩坑：

- 从服务器**内部** `curl` 自己的公网 IP 会得到 `Connection refused` —— 这是 NAT 不支持回环的正常现象，**不代表面板有问题**，别在这上面排查；
- **DST 的游戏端口同样需要在这里配置**，而且是主世界 3 个 + 洞穴 3 个一共 6 个 UDP，外部端口必须与内部一致 —— 完整清单与判断方法见 5.4 节。

### 6.2 读取初始密码

安装器生成随机初始密码，默认不在摘要中明文展示。在服务器上执行：

```bash
sudo sed -n 's/^ADMIN_PASSWORD=//p' /opt/game-server-hub/panel.env
```

默认管理员用户名是 superadmin。也可以在首次安装时显式指定账号密码：

```bash
# 脚本默认 tag 决定安装版本；如需锁定别的版本，在 sudo env 里追加 GSH_RELEASE_TAG=v0.10.0
curl -fsSL https://raw.githubusercontent.com/PMAT77/game-serve-hub/v0.10.0/scripts/install.linux.sh \
  | sudo env ADMIN_USERNAME=admin ADMIN_PASSWORD='替换为强密码' \
      bash -s -- --mode native
```

### 6.3 强制修改密码

**首次登录会强制跳转到改密页**，必须设置符合强度要求的新密码后才能进入面板。这是安全设计：初始密码曾以明文存放在服务器磁盘上。

### 6.4 日常修改密码

登录后点击**右上角头像 → 个人资料**，在个人资料页选择**修改密码**，输入旧密码与新密码提交即可。建议定期更换。

### 6.5 忘记密码

- 尚未在面板内改过密：用 6.2 的命令从 panel.env 重新读取初始密码；
- 已在面板内改过密：密码以数据库中的凭据为准，panel.env 里的初始密码不再有效。不要通过反复重跑安装器来"重置"密码——同模式重跑是原地升级，不会覆盖你在面板里改过的账号。

## 7. 进入面板后的操作流程总览

登录后落到**主页**：一个产品总览页，列出各功能模块，并在右上角给出「进入实例管理」「项目文档」「GitHub」三个入口。

按下面的顺序操作，即可完成一次完整开服：

| 步骤 | 页面 | 做什么 |
| --- | --- | --- |
| 1 | 实例管理 | 确认"运行环境与安装镜像"就绪（见第 8 章） |
| 2 | 实例管理 | 创建实例（见第 9 章），自动下载安装游戏本体（见第 10 章） |
| 3 | 房间管理 → 房间设置 | 配置房间名称、联网方式、Klei 令牌、洞穴开关与白名单预留位（见第 11 章） |
| 4 | 世界管理 → 世界设置 | 配置地上/洞穴的世界规则与生成参数（见第 12 章） |
| 5 | 模组管理（可选） | 搜索并订阅创意工坊 Mod（见第 14 章） |
| 6 | 实例管理 | 启动实例，首次启动自动生成地图（见第 15 章） |
| 7 | 实例管理 / 监控台 | 观察日志确认启动成功，玩家进服 |
| 8 | 玩家管理 | 维护管理员、白名单与黑名单，踢出或封禁捣乱的玩家（见第 19 章） |
| 9 | 备份与恢复 / 计划任务 | 配置日常备份与定时任务（见第 17、18 章） |

面板左侧导航依次为：

- **监控台**：主机资源总览
- **实例管理**：实例列表 / 详情 / 控制台
- **房间管理**、**世界管理**、**玩家管理**、**模组管理**：DST 的房间、世界、玩家名单与 Mod 配置
- **备份与恢复**、**计划任务**：存档备份、数据库快照与定时任务
- **系统设置**：面板与游戏版本、网络与端口；告警渠道在它的「通知渠道」tab 里

### 7.1 监控台

**监控台** 是左侧导航第一项，展示宿主机与实例的资源总览：CPU、内存、磁盘、网络，以及当前内存档位与建议。常用场景：

- 开服前后确认可用内存与磁盘余量；
- 玩家反馈卡顿时，判断是主机负载还是游戏本身的问题；
- 安装 / 更新期间观察资源峰值（SteamCMD 峰值约 1～1.5 GiB）。

可用内存不足时，安装或启动会被拒绝并返回错误码 `HOST_MEMORY_PRESSURE`，此时按[内存建议](MEMORY.md)调整档位，或先停掉其它实例。

### 7.2 通知设置

**系统设置 → 通知渠道** 用来配置事件通知渠道（钉钉、企业微信、飞书、Server酱、PushPlus、通用 Webhook、Telegram），接收实例异常退出、内存阈值等事件。其中：

- **通用 Webhook**：面板向你的 https 地址 POST 一段 JSON，字段为 `source`、`severity`、`title`、`message`、`text`、`at`，方便接自建告警或中转；
- **Telegram**：填写 @BotFather 给的 Bot Token 与接收消息的 Chat ID（群组 ID 为负数，频道可用 `@频道名`）；
- 渠道配置在保存时就会校验格式（Webhook 必须 https、Token 与 Chat ID 形状），避免等到事件触发才发现发不出去。

通知只做提醒，不会代替面板里的操作；告警平台集成（Prometheus、PagerDuty 等）尚在计划中，见[架构与产品边界](ARCHITECTURE.md#运维能力的-community--pro-细分)。

### 7.3 环境自检

**系统设置 → 环境自检** 一键检查运行环境、SteamCMD 就绪情况、磁盘余量、内存档位、数据目录可写、实例状态与通知渠道，每项给出实测结论与下一步动作；「复制结果」可以把整段结果贴到群里或 Issue 里。

面板不对劲时先跑一遍自检：它能区分"面板本身的问题"和"运行环境的问题"，比逐条对照文档快得多。服务器上还有命令行版体检 `gsh doctor`（安装器会布置），两者检查的维度一致。

## 8. 检查更新：运行环境与镜像版本

开服前和日常维护时，有两个地方负责"更新与运行环境"：

### 8.1 实例管理页：运行环境与安装镜像

打开 **实例管理** 页，顶部是"运行环境与安装镜像"折叠面板：

- 状态标签显示运行时（Docker/systemd）是否可用、SteamCMD 是否就绪、DST 运行镜像是否就绪；
- 未就绪时点击 **预拉游戏安装镜像**（Native 模式为 **检查 SteamCMD**）提前准备；
- Docker 模式还可以点 **手动拉取 DST 运行镜像**；
- 面板默认会在创建实例时自动准备镜像，这个面板用于提前检查或补拉。

### 8.2 系统设置页：面板与游戏版本

打开 **系统设置**，找到"面板与游戏版本"区块：

- 显示当前统一镜像版本（面板 + DST 运行环境 + SteamCMD 同版本）、本地与远端摘要、最新 Release 信息；
- 点击 **检查更新** 立即向镜像仓库/GitHub Release 核对；有新版本且 Docker 栈可达时，先点 **下载更新**（版本行下方显示实时下载量，如 `已下载 512 MB / 1.2 GB`），下载完成后按钮变为 **立即安装**，点击后重建面板（会短暂重启管理端，实例存档与配置不受影响）；
- **更新下载源**可选「自动（推荐）」「仅离线镜像包」「仅镜像仓库」。自动档会优先下载 Release 离线镜像包（经加速代理、校验同名 `.sha256` 后 `docker load` 导入，并实时显示下载量），失败才回退镜像仓库拉取。下载中断会保留分片、下次从断点续传，开始前也会检查剩余磁盘空间。面板里的选择优先于 `GSH_PANEL_UPDATE_SOURCE`；
- Native 模式显示手动升级命令（重跑新版安装脚本原地升级）；
- "面板镜像自动检查更新"开关可设 1–168 小时的自动检查间隔；
- "启动前检查游戏更新"开启后，每次启动实例前会向 Steam 核对服务端 Build ID，有新版本时会阻止启动，提醒你先更新游戏服务端。

游戏本体的版本更新（DST 出新补丁时）在**实例列表**的"更新服务端"操作里执行，见 10.3 节。

## 9. 创建实例

一个实例 = 一个独立的 DST 服务器（一套集群）。可以创建多个实例开多个服。

1. 进入 **实例管理**，点击 **创建实例**；
2. 填写表单：
   - **实例名称**：自定义，便于识别（也会成为默认房间名，后面可改）；
   - **游戏**：选择《饥荒联机版》（AppID 322330）；
   - **安装路径**（可选）：默认由面板统一管理，一般不用改；
3. 提交后实例以"未安装"状态出现在列表中，随后**自动开始安装**（见第 10 章）；
4. 安装过程中状态为"安装中"，点击实例可查看安装日志；完成后状态变为"已停止"，并会弹出"准备启动服务器"引导（见第 15 章）。

统计卡（全部/未安装/安装中/运行中/已停止/异常）可以直接点击筛选实例。

### 9.1 开第二个服（多实例）

同一个面板可以创建多个实例，每个实例是一套独立的集群。多实例要注意三件事：

1. **端口不能重复**：每个分片占 3 个 UDP 端口（见 [12.3 分片端口说明](#123-分片端口说明)），第二个实例要换一组，例如地上 `11001/8767/12347`、洞穴 `11002/8769/12349`，并在安全组与 NAT 转发里同步放行。启动时面板会检测端口冲突，让你选择手动改端口或自动分配。
2. **内存是共享的**：每个地上分片约 0.5～1.5 GiB，开洞穴再加 0.4～1 GiB；按[内存建议](MEMORY.md)的档位预留，不要把多个实例塞进 4 GiB 机器。
3. **安装不要并行**：SteamCMD 峰值约 1～1.5 GiB，安装或更新前先停掉运行中的实例，避免宿主机 OOM。

## 10. 下载安装饥荒游戏本体

### 10.1 自动安装

创建实例后，面板自动调用 SteamCMD 下载 DST 专用服务器完整本体：

- Docker 模式在 SteamCMD 容器内执行下载；
- Native 模式使用 /opt/game-server-hub/runtime/steamcmd 的本地 SteamCMD；
- 安装过程逐阶段可见：打开实例详情或列表中的 **安装日志**，能看到校验与下载进度。

### 10.2 国内下载慢？

- 安装服务器时使用 --network cn（将 SteamCMD 下载区域设为中国区、重试提高到 8 次）；
- 也可在 panel.env 配置 GSH_STEAMCMD_DOWNLOAD_REGION=cn、代理等参数后重启面板（见 [INSTALL.md · SteamCMD 下载慢或失败](INSTALL.md#steamcmd-下载慢或失败装游戏时)）。

### 10.3 更新游戏服务端

DST 出新版本后：

- 若系统设置里开了"启动前检查游戏更新"，启动时会被提醒先更新；
- 在实例列表的操作菜单里点 **更新服务端**，面板会用 SteamCMD 校验并补齐到最新 Build；更新前会**自动创建一份存档备份**（防止更新破坏世界）；
- 更新过程中实例不可启动，完成后正常启动即可。

## 11. 创建房间

"房间"是玩家在游戏内联机列表看到的服务器信息。进入 **房间管理**，点击实例进入 **房间设置**：

| 设置项 | 说明 |
| --- | --- |
| 联网方式 | **公网联机**：任何人可从列表搜到（需 Klei 令牌）；**局域网**：仅同内网可见；**离线**：单机模式不联网 |
| Klei 集群令牌 | 公网联机**必填**，pds- 开头（获取方法见 2.2 节）；已配置过时留空表示不修改 |
| 房间名称 | 必填，联机列表显示的名字 |
| 房间描述 | 列表中展示的简介 |
| 房间密码 | 留空为公开服；填写后只有知道密码的玩家能进 |
| 游戏模式 | 生存（默认）/ 无尽 / 荒野 / 轻松 / 暗无天日，选择后下方有模式说明 |
| 最大玩家数 | 1–64，默认 6 |
| PvP | 是否允许玩家互相伤害 |
| 无人暂停 | 服务器空人时是否暂停世界推进 |
| 网络刷新率 | 15–60，默认 15；越高越流畅但对带宽和 CPU 要求越高 |
| 洞穴开关 | **开启洞穴**后创建世界会出现洞穴分片（会额外占用约 1–2 GiB 内存，低配机器有提醒） |
| 白名单预留位 | 给白名单玩家保留的席位数量，填 0 表示不使用白名单；名单本身在「玩家管理」页面维护（见第 19 章） |
| Steam 组限制 | 可限制仅指定 Steam 组成员入服（进阶） |

填完点击 **保存并重启**（实例运行中改动需重启生效；未启动过的实例保存后下次启动生效）。

> 令牌保存后不会明文回显，只显示掩码，属于正常现象。

## 12. 创建世界

世界在**首次启动实例时自动生成**，你要做的是提前把规则配好。进入 **世界管理**，点击实例进入 **世界设置**，页面分为"地上 / 洞穴 / 模组"三个页签（洞穴页签需先在房间设置开启洞穴）。

> 世界规则与地图生成参数**只在生成地图时生效**：面板把它们写进 `worldgenoverride.lua`（预设 + 全部覆盖项），游戏在第一次生成地图时读取。地图生成后再改这里不会改变现有存档，只在该分片重新生成地图（例如删掉 `<分片>/save` 目录后重启）时生效——世界已生成时，「世界规则」页签内会提示这一句。

### 12.1 地上世界（Master）

- **世界规则**：按分组调整玩法细节——全局、活动、冒险家、世界、资源再生、非自然传送门资源、生物、敌对生物、巨兽、月亮变异等，每项可一键恢复默认档位；
- **世界生成**：预设默认为**联机生存**（SURVIVAL_TOGETHER）；地图生成后，部分世界生成选项将无法再改，想改尺寸/群落要趁生成前；
- **网络**：游戏端口 10999、Steam 认证端口 8766、Steam 主服端口 12346（默认即可，见 12.3）。

### 12.2 洞穴世界（Caves）

- 世界生成预设可选**标准洞穴**、**资源丰富**、**完全黑暗**等；
- 规则分组与地上类似，但面向洞穴生态；
- 洞穴地图在洞穴服务器首次启动时自动生成。

### 12.3 分片端口说明

每个分片有三个 UDP 端口，默认值：

| 分片 | 游戏端口 | Steam 认证端口 | Steam 主服端口 |
| --- | --- | --- | --- |
| 地上（Master） | 10999 | 8766 | 12346 |
| 洞穴（Caves） | 11000 | 8768 | 12348 |

一般无需修改。若改成其他端口，注意：端口不能与另一分片重复；安全组要放行新端口。

### 12.4 世界维护：存档点、回档与重置世界

**世界管理 → 世界设置** 页底部（地上 / 洞穴页签下各一份）提供三项能力：

- **存档点**：显示当前分片读到的存档点数量与时间。世界首次启动后，游戏会在新的一天开始时自动保存一份快照，保留数量由房间设置里的「最大快照数」决定；
- **回档**：选择回退步数后确认执行。回档会把世界退回若干存档点之前，**执行前会自动创建一份「回档前」安全备份**，回档过头还能在「备份与恢复」里找回来；
- **重置世界**：丢弃当前世界并重新生成地图，需要手动输入实例名称二次确认；执行前同样会自动创建安全备份。

实例未运行时这些能力不可用：命令要送到正在运行的游戏进程里。

控制台页与实例详情页的「命令中心」也提供回档与重置世界的快捷按钮，但那两个入口是直接下发命令、不会自动备份；想要"操作错了还能翻回去"，用世界设置页的入口。

### 12.5 世界种子

**世界种子**一栏就是这张地图的种子，地上与洞穴各一个、互不影响。

- 实例**运行中它锁定**，显示的是当前世界正在用的种子（面板会从游戏里读出来记下，**停服后依然显示**）；运行中点旁边的 **读取** 可随时再取一次；
- 实例**停止后可以改**：填 1–15 位数字，点旁边的 **重置世界**，面板会先自动创建一份安全备份，再丢弃当前世界、按这个种子重新生成地图并启动实例——**首次生成地图需要几分钟**；
- 留空 = 新地图由游戏随机生成；
- 想复现同一张地图，除了同一种子，还要**同一套世界生成参数与同一份 Mod 组合**（Mod 参与地图生成，游戏版本差异同样会影响结果）；
- 也可以自己查种子：服务器控制台执行 `c_announce(GetWorld().meta.seed)` 会向世界里广播，玩家在游戏内控制台执行 `print(TheWorld.meta.seed)` 也能看到。

> 「世界维护」里也有一个**重置世界**，那是另一件事：它把命令直接发给运行中的游戏，用来快速重开一张图（沿用当前种子），不改种子，也不需要停服。

> **关于「先看看这个种子长什么样」**：面板**不提供**「不开服就按种子试算地形」——DST 本身没有这种接口，地形只在游戏生成地图时才产生。但面板提供**看已经生成的世界长什么样**：见下一节的地形图。

### 12.6 地形图

「世界设置 → 地形图」可以把**当前世界的地形**导出成一张图，用来选址、看地标分布、留档。

- 图是**从正在运行的游戏里读出来的**：面板让专用服把每个格子的地块类型读出来发回面板，再自己渲染，所以图反映的是游戏眼里真实的地形，不是估算；
- **实例停止时无法生成**（没有活着的世界可读），界面会直接说明；
- 图里**含当前启用的 Mod 影响**——Mod 会改地形，所以同一套世界设置在不同 Mod 组合下画出来的图不一样；
- **不显示玩家位置**，只画地形；
- 点「生成地图」后需要几秒；同一张图在三分钟内重复查看不会再去打扰游戏，点「重新生成」则强制重画。

**图怎么看**

- 图下方（宽屏时在右侧）有**图例**：图上出现过的每一种地块都列出来，带色块、中文名与占比（如"森林 8.4%"），按占比从大到小排。颜色是面板自己定的（不追求与游戏内小地图一致），但图例里的颜色和图上完全一致；
- 图例里还会列出**地标**：洞穴入口、虫洞、复活石、远古大门、猪王、猪人房、鱼人房、月台遗址、格罗姆雕像、章鱼王、海象营地、高鸟巢、蜘蛛巢、兔洞、蜂巢、蚁狮、蜂后巢、龙蝇、触手。**每个地标有各自的颜色**，并按类别用三种形状区分——**圆点是通道、方块是建筑、菱形是巢穴**，图例里的形状与图上一致；
- 图上每 50 格有一条浅灰网格线，用来估算距离；地形的每块边界有细描边，大陆轮廓看得出来；
- 地图默认按面板宽度限制在约 560 像素高以内显示，**点一下地图可以放大看原图**（原图是每格 3 像素渲染的，放大后依然清晰）；
- 图例里若出现**带「未收录」字样的地块**（如 `Ice Floe（未收录）`），说明游戏里有这块地、但面板还没有它的正式配色：它会被排在图例最前面、用醒目颜色标出，图上按地形号给了一个稳定可区分的颜色。这类地块通常来自游戏新版本或 Mod，不影响到其余部分。

> 换过世界（重置世界、按种子重开）之后，记得点一次「重新生成」，否则看到的是上一张图。

## 13. 主世界端口、洞穴端口需要手动开放吗？

**需要。** 面板只负责配置和启动游戏进程，不会替你操作云厂商的安全组；安装器也默认不修改本机防火墙。因此：

- 主世界的 10999/8766/12346（UDP）**必须手动放行**，否则玩家连不上；
- 开启洞穴后，11000/8768/12348（UDP）**同样必须手动放行**，否则会出现进洞穴崩线、世界加载卡住等问题；
- 宿主机在 NAT 转发后面时，安全组之外还要在平台 / 路由器的端口转发里**按与内部相同的端口**为这 6 个 UDP 各加一条规则（见 5.4 节）；
- 放行方法见第 4 章。

常见误区：只放行了面板的 9527/tcp 就以为开好了——面板能打开不代表游戏能连。玩家反馈"搜不到房间/进不去"时，第一件事就是核对安全组 UDP 规则。

## 14. 安装与管理 Mod

1. 进入 **模组管理**，选择目标实例；
2. 在创意工坊列表中搜索 Mod（可按订阅数等排序），或直接输入创意工坊 ID；
3. 点击 **订阅**，面板自动通过 SteamCMD 下载 Mod 文件，列表中状态变为"已订阅"；
4. 点击 Mod 进入 **Mod 详情**，可调整该 Mod 的配置参数；
5. 回到 **世界设置** 的"模组"页签，把 Mod **开启**（开启对实例生效：地上与洞穴共用同一份 Mod 列表）；
6. 保存并重启实例生效。

订阅成功的 Mod 会引导你到世界设置开启；只订阅不开启是不会生效的。

列表里的两列各管一件事，别把它们看成一回事：**安装状态**说的是 Mod 文件在不在服务器上（**已就绪** / 下载中 / 下载失败；文件没就绪时开启按钮点不动），**开关状态**说的是它在这局游戏里生不生效。悬停在状态标签上会给出同样的说明。

### 14.1 更新已订阅的 Mod

面板启动服务器时会跳过游戏自身的 Mod 更新检查，**Mod 的更新由面板负责**。因此 mod 作者发布新版本后，需要你在面板里更新一次，否则新玩家进服时会看到"服务器启用了一些老版本的 Mod"并被断开——老玩家的本地缓存与新玩家刚下载的版本对不上，游戏就会拒绝连接。

1. 在 **模组管理 → 已订阅** 页签点 **检查更新**：面板会比对工坊上的最新版本与本机内容，逐个标出 **已是最新 / 有新版本 / 未检查**，顺带把导入存档时没识别出来的 Mod 名称和缩略图按创意工坊信息补全；
2. 只有 **有新版本** 的 Mod 才会出现 **更新** 按钮；可以逐个更新，也可以点 **全部更新 (N)** 一次更新所有有新版本的 Mod；
3. 更新完成后 **重启实例**：新内容在下次启动时才会被游戏加载。

平时列表里的版本状态由面板后台定期检查（约 6 小时一次），不用每次手动点。看到 **未检查** 说明信息不足（尚未检查、本机找不到该 Mod 的版本记录，或者工坊上已经找不到它），这类 Mod 会给一个 **重新下载** 按钮，把本机内容重新对齐一次。

面板判断"本机这份 Mod 是哪个版本"有两个依据：SteamCMD 下载清单里记的版本时间，以及内容文件自己的落地时间（`steamapps/workshop/content/322330/<id>`）。两者都取不到就显示 **未检查**——**信息不足时不会猜成"已是最新"**，所以"检查更新"的提示只要提到还有 Mod 无法判断，就说明那几行的版本还没被确认，需要按提示点 **重新下载**。另外面板还会顺带比对本机已下载内容与游戏实际加载的那份（`ugc_mods`），后者更旧时会直接标成 **有新版本**：这种情况内容其实已经下好，缺的是重新落位，点一次 **更新** 即可。

> 这一版才引入上述版本检测：如果你的列表里没有「版本」列、每个 Mod 都带「更新」按钮，说明页面跑的还是旧界面——先把面板升级到最新版（见[安装指南 · 升级](INSTALL.md#升级)），**并在升级后刷新浏览器页面**，再按上面的步骤操作。

### 14.2 导入存档后 Mod 没下全

导入外部存档时，面板按源存档的 Mod 清单重建订阅记录，并把本机缺少的 Mod 排进下载队列。**下载队列是串行的，Mod 多时需要等一会儿**：列表上方的概览会显示 `共 N · 就绪 X · 下载中 Y · 失败 Z`。

- **下载中** 的行会自动刷新，不用手动干预；
- **失败** 的行会给出原因（悬停在状态标签上可见），可以点 **重试全部失败 (Z)** 一次性重新排队；
- 重启实例前请确认失败数为 0：面板只会把已就绪的 Mod 写进服务器清单，没下完的 Mod 在游戏里就是不存在的。

## 15. 启动服务器

回到 **实例管理**，点击实例的 **启动**：

- **首次启动**会弹出"准备启动服务器"引导：
  - 若联网方式为公网但未配置 Klei 令牌，会直接引导你"去配置房间"——没有令牌不允许公网启动；
  - 可选择 **按当前配置启动**（已保存房间/世界设置时）或 **用默认配置启动**（直接使用离线房间和默认地图）；
  - 确认后面板按配置生成第一张地图（洞穴在洞穴服务器首次启动时同样生成）；
- **日常启动**：直接点启动即可；
- 启动后状态变为"运行中"，在实例详情能看到地上/洞穴两个分片的运行状态、资源占用，以及"连接信息"。

玩家进服方式：打开《饥荒联机版》→ **浏览游戏**，按房间名搜索即可。

> 地图生成后，多数世界生成选项不可再改。想换地图风格需要重置世界（控制台的 c_reset()，见 16.2）并重新生成。

## 16. 实例控制台

入口：**实例管理 → 实例详情 → 控制台**（或列表操作菜单中的"控制台"）。控制台是日常管理最常用的页面。

### 16.1 界面与页签

- **控制台页签**：日志与命令在同一个页签内。上半是实时日志（地上与洞穴的游戏运行日志合并展示，每行带分片标签），下半是命令输入区——**命令回显与执行结果都出现在上方日志中**，不用切换页签；命令回显行带琥珀色文字与左侧竖线，便于在密集日志里定位自己刚发的命令；
- **显示过滤**：日志区上方的「显示」可切换 **全部 / 面板消息 / 游戏输出**。默认「全部」（面板消息与游戏原始日志按时间混排）；只想看游戏自身的输出时切到「游戏输出」；
- **日志工具条**：清空日志、复制日志（复制当前可见内容）、下载日志、历史日志，以及自动滚动开关；面板内只保留最近 2000 行；
- **落盘日志**：控制台日志同时写入 `<数据目录>/install-logs/console/<实例 ID>.log`（Docker 模式在数据卷内，Native 模式在 `/var/lib/game-server-hub/` 下）。单个文件超过 5 MiB 自动轮转，保留当前文件加两个历史文件；删除实例时一并清理。面板重启后仍能翻到上一次运行的游戏日志，这是排查"半夜掉线"这类问题的关键；
- **维护公告页签**：向游戏内全体玩家推送公告（编辑内容后一键推送），并保留推送历史。

### 16.2 发送命令

- 顶部命令输入框输入 DST 控制台命令（如 c_save()），点击发送；
- 可用单选切换命令送达的分片：**地上 / 洞穴**（洞穴未启用或未运行时不可选并有提示）；
- 实例**详情页**还有"命令中心"，提供常用操作的按钮化封装：

| 快捷命令 | 作用 | 风险 |
| --- | --- | --- |
| 保存 c_save() | 立即保存当前世界 | 无 |
| 回档 1/2/3 天 c_rollback(n) | 世界回退到 n 个游戏日前的存档点 | 有危险确认 |
| 重置世界 c_reset() | 丢弃当前世界并重新生成全新地图 | 有危险确认，不可恢复 |

自定义命令可发送任意 DST 控制台指令（公告 `c_announce()`、保存 `c_save()` 等），回显与执行结果都会出现在控制台上方的日志里。踢人与封禁请用「玩家管理」页面：它会先确认命令发得进房间，再复查在线名单确认操作真的生效，没生效时自动补发一条；**房间主人自己的账号踢不掉、也封不掉**（那条连接就是服务器本身，封了等于把房主自己关在门外），界面会直接说明原因。一定要在控制台手动执行时，正确的命令是 `TheNet:Kick("KU_xxx")` 与 `TheNet:Ban("KU_xxx")`。

### 16.3 什么时候用控制台

- 启动后看日志确认分片启动与互联成功；
- 玩家反馈异常时实时观察报错；
- 定期手动 c_save()（日常建议交给计划任务自动备份）；
- 世界出问题（地形改版、存档损坏）时回档或重置。

### 16.4 文件管理（实例目录）

实例详情页底部的 **文件管理** 用于直接查看实例目录、编辑文本配置：

- 目录浏览：从实例目录根开始，点目录名进入、点面包屑返回；符号链接不会出现在列表里；
- **关键配置文件**：卡片顶部给出房间配置、地上 / 洞穴的世界与 Mod 配置的直达按钮（文件存在时才显示），不用在目录树里翻路径；
- 编辑文本：点文件名打开编辑框，保存后立即写入。支持 `.ini`、`.lua`、`.json`、`.txt`、`.cfg`、`.log` 等文本类型；
- 保存前会自动备份原文件（同目录下生成带时间戳的 `.bak` 文件），写错内容可以拿回来；
- 重命名与删除：只作用于实例目录内，删除不进面板备份、不可撤销；
- **上传**：点「上传到当前目录」把本地文件放进当前所在目录（例如把改好的配置直接传回 `Cluster_1`）。同名文件会**先备份再覆盖**，下载与上传都有进度提示；
- **下载**：文件行右侧点「下载」取走单个文件（敏感文件不提供下载）；
- 限制：单个文本文件读写上限 1 MiB，超过只显示前 1 MiB 并提示（此时直接保存会截断，请先自行备份）；上传单文件默认上限 256 MiB；集群令牌等敏感文件会标注「敏感」，不提供查看、编辑、上传覆盖、重命名、删除与下载。

要搬运整套存档（换机器、导入别人的存档）仍请走 **备份与恢复**：它会把世界数据、房间配置与令牌一起打包或还原，比逐个文件传更可靠。

## 17. 备份与恢复

进入 **备份与恢复** 页面。这里管理所有实例的存档备份与面板数据库快照，日常备份**不再需要 SSH**。

这一页有**两类互不相干的东西**，先分清再操作：

| 页面上的东西 | 是什么 | 用来干什么 |
| --- | --- | --- |
| 存档备份（手动、定时，以及各种"XX 前"的自动安全备份） | 某个实例**整个世界**的打包文件 | 出事时 **回档**到某个时间点；也可以下载到本地留存 |
| 面板数据库快照 | 面板**自己**数据库的副本（账号、实例记录、面板设置） | 面板升级或换机前留存；**不含任何游戏存档**，也不能用来恢复游戏 |

要**换一台机器**开服，用的是第三个东西：实例详情页的「导出迁移包」（见 17.7）——它导出的包同样可以走 17.4 的「导入外部存档」。

### 17.1 创建存档备份（手动）

1. 页面顶部选择目标实例；
2. 点击 **创建存档备份**，可填写备注（如"开服首日存档"）；
3. 面板把该实例的 klei-storage（世界数据、房间配置、集群令牌）打包为 tar.gz；**实例运行中会先自动执行 c_save() 保存世界再打包**，不用担心丢进度；实例已停止时直接打包当前存档。

### 17.2 恢复备份

1. 在列表中找到目标备份点，点击 **恢复**；
2. 确认弹窗会提示：**恢复要求实例已停止**（运行中会被拒绝），且恢复前会**自动创建一份"恢复前"安全备份**，恢复错了还能再翻回去；
3. 恢复完成后启动实例，验证世界状态即可。

### 17.3 下载与删除

- **下载**：点击备份的下载按钮，把 tar.gz 保存到本地电脑，实现异地容灾（重要服建议定期下载）；
- **删除**：删除单个备份文件，不可恢复。

### 17.4 导入外部存档

点击 **导入外部存档**，上传本地 Klei 存档压缩包（.zip / .tar.gz / .tgz）：

- 支持压缩整个 Cluster_x 目录，或整个 DoNotStarveTogether 目录，面板下载的备份包与实例详情页导出的迁移包也都可直接导入；
- 导入要求实例已停止且已完成游戏安装；
- 导入前自动创建"导入前"安全备份；上传后面板会先探测识别存档结构并提示警告。

适用场景：把本地/旧服务器的世界搬到这台服务器，或把下载的备份恢复到新实例。

### 17.5 面板数据库快照

点击 **创建面板数据库快照**，对面板 SQLite 数据库做一致性快照（VACUUM INTO），包含实例、账号与面板设置，**不含任何游戏存档**。

快照列表的每一行可以 **下载**、**恢复**与**删除**：

- **下载**：把 `.sqlite` 文件取回本地，服务器整个坏掉时至少还留着账号与实例清单；
- **导入快照**：把外部拿到的 `.sqlite` 上传进来（例如别的机器导出的、或你本地留存的那份）。上传只入库、不会自动恢复，面板会先校验它是不是本面板的数据库、是不是来自更新的版本，不合格的直接拒绝；
- **恢复**：用选中的快照**替换面板当前的数据**。确认框要求手工输入「恢复面板数据」，确认后面板会自动重启（几秒到十几秒），期间页面无法访问，**当前登录也会失效**——快照里的账号是当时那一份。恢复前面板会自动再做一份快照作为退路，恢复后如果新库不可用，启动时会自己回退到恢复前的数据，不会把面板卡成打不开。

两点要知道：**正在运行的游戏实例不受影响**（它们由容器/系统服务独立管理，恢复面板数据不会碰游戏存档）；恢复回退的是面板侧数据，磁盘上的实例目录不会跟着回退，所以快照之后新建的实例会从列表里消失、之后删掉的实例记录会冒出来——到实例列表里对账一下即可。

升级前的数据库备份由安装脚本自动完成，与这里的快照互不替代。

### 17.6 保留策略与自动备份

- 每个实例默认保留最近 **10 份**存档备份，超出自动淘汰最旧的；
- 系统级自动备份钩子默认开启：**更新服务端前**、**删除实例前**自动创建备份，备份类型分别标记为"更新前""删除前"；
- 备份文件在服务器上位于 /var/lib/game-server-hub/backups/（Docker 卷 gsh-backups）；
- 面板内备份不等于异地容灾，重要服务器请配合定时下载到本地。

### 17.7 导出迁移包（换机器）

入口在**实例详情页**的「迁移到其他机器」卡片，不是本页面。它和存档备份解决的不是同一件事，别混用：

| | 存档备份 | 导出迁移包 |
| --- | --- | --- |
| 留在哪 | 服务器的备份列表里，可恢复、可下载 | 只是一次导出，**不进备份列表，24 小时后自动清理** |
| 干什么用 | 本机**回档** | 交给**另一台机器**（新服务器、接手的人） |
| 附带信息 | 无 | 迁移报告：分片端口、Mod 清单、玩家名单、迁移前要确认的风险项 |
| 包内内容 | 世界数据、房间配置、集群令牌 | 同上，另不含游戏本体与 Mod 文件 |

步骤：先点 **检查迁移报告** 逐条确认风险项（报告不含集群令牌与房间密码，可以放心转发），再点 **导出迁移包** 下载 tar.gz；到目标机器上创建实例后用 17.4 的「导入外部存档」导入。目标机器还没装面板、或者存档在旧机器上而不在这个面板里时，用命令行脚本 `scripts/export-cluster-archive.ts`，产出同一种包。

## 18. 计划任务

进入 **计划任务** 页面，把重复性运维交给定时器。支持四种任务：

| 任务类型 | 作用 |
| --- | --- |
| 定时备份（实例存档） | 到点对所选实例执行一次存档备份；与 17.1 的手动备份**是同一种备份**，只是到点自动执行，运行中也会先自动保存世界 |
| 定时重启 | 到点重启实例；适合每日凌晨清内存、应用更新 |
| 更新检查（SteamCMD） | 到点向 Steam 核对游戏版本，有新版本时提醒你更新 |
| 面板数据库快照（面板全局） | 到点对面板 SQLite 做一致性快照 |

**调度方式**（二选一）：

- **每日固定时刻**：如 04:30，时区可选 **北京时间**（默认）或 **服务器所在时区**；
- **每 N 小时**：间隔 1–168 的整数小时。

**创建步骤**：

1. 点击 **新建任务**；
2. 选择目标实例（面板数据库快照任务的目标固定为"面板数据库"）、任务类型；
3. 选择调度方式并设置时刻/间隔；
4. 保存后任务进入列表，可随时 **编辑**、**删除**，列表中还能看到每个任务最近一次的执行结果（成功/失败/跳过）。

推荐配置：每日凌晨定时重启 + 每 6 小时定时备份 + 每日面板数据库快照。

## 19. 玩家管理（在线玩家与名单）

入口：左侧主导航的 **玩家管理**。它是一个独立页面，和「房间管理」一样先列出各个房间，点 **管理玩家** 进入该房间的玩家页面。

玩家页面分两块：

- **在线玩家**：此刻正在房间里的人，按地上与洞穴分开列出，每 15 秒自动刷新；
- **玩家名单**：管理员、白名单与黑名单三份名单，改动立即保存。

名单决定「谁有资格进来」，在线玩家显示的是「此刻在房间里的人」，两者不是一回事：名单为空而在线人数不为 0 是正常的。

三个名单的作用：

| 名单 | 作用 |
| --- | --- |
| 管理员 | 名单内的玩家可在游戏内使用控制台命令 |
| 白名单 | 为指定玩家保留席位，仅在「白名单预留位」大于 0 时生效 |
| 黑名单 | 名单内的玩家无法加入房间 |

### 19.1 加入与移出名单

1. 切到要维护的名单页签；
2. 在输入框填 **游戏名** 或 **玩家 ID**，点 **加入名单**：
   - 填游戏名时，面板先在玩家记录里查找：只匹配到一位就直接加入，匹配到多位会列出来让你确认；
   - 填 `KU_` 开头的玩家 ID 可以直接加入，多个 ID 用空格或逗号分隔；
3. 点某一行的 **移出** 把玩家移出名单。**移出黑名单要特别注意**：游戏只在启动时读取黑名单，运行中的房间把封禁记在内存里，所以删掉名单里那一行并不会立刻解封——被移出的人仍然会被拒绝加入。因此房间运行时点「移出」，面板会直接问你要不要**移出并重启房间**，选它即可当场解封（房间里的玩家会断开一次）；
4. 点某一行的 **备注** 可以给认不出来的 ID 起一个备注名。备注只存在面板里，不写进游戏，也不影响玩家能否加入。

面板记录里的名字来自两处：玩家在线时自动记录，以及点名单卡片右上角的 **从日志补全玩家名** 从服务器日志里补全。**从未在本服出现过的玩家查不到名字**，这时请直接填玩家 ID，加入后也能在列表里看到它。

名单文件在房间配置目录中，保存时写入的仍是玩家 ID——游戏的名单文件只认 ID，名字只是面板侧的显示。

### 19.2 踢出、封禁与快捷加名单

在线玩家的每一行都提供四个操作（标记为「临时身份」的行只剩「踢出」可用，原因见下方注意事项）：

- **踢出**：把该玩家立刻移出房间。对方可以马上重新加入，适合临时清场或让卡住的玩家重连；
- **封禁**：把该玩家加入黑名单并立刻踢出，之后他无法再加入房间，**房间重启后依然有效**；
- **加入白名单 / 设为管理员**：把当前在线的人直接加进对应名单，不必手抄玩家 ID。

注意事项：

- 四个操作都会先弹确认框，封禁会改变房间的准入配置，确认对象无误再点；
- 面板在命令下发后会**复查在线玩家**，确认对方已经离开才提示成功；提示「没能踢出／没能封禁」时点刷新再看一次，必要时重试（命令原文与游戏输出都在控制台日志里）；
- **房间主人自己的账号只能「移出世界」，不能「踢出」**：那条 `[Host]` 连接就是服务器本身，与房主共用同一个玩家 ID（因为集群令牌属于房主账号），游戏按 ID 找连接会落到那条假连接上，断开它做不到。所以对房主点「踢出」时面板改用官方的 `c_despawn`：把他送回角色选择界面，数据照存档保留、重新选角色即可再进，提示也如实写成「已把某某移出世界」。**封禁房主则会被直接拒绝**——黑名单一旦写下他自己的 ID，重启后连他自己都进不来；
- **封禁立刻生效，解封必须重启房间**：封禁会同时写黑名单并让房间当场拒绝该玩家；反过来，把人移出黑名单后房间内存里仍记着这条封禁，必须重启房间才能解除。面板会在移出黑名单时直接问是否一并重启；
- 玩家在洞穴时，列表会把他归到「洞穴」一组，踢出与封禁同样有效；
- **没有 Klei 账号的玩家**（离线或局域网进来的路人）会照常出现在在线列表里，标成「临时身份」：可以踢出，但**不能封禁、也不能加入名单**——游戏每次进服都会给他一个新的临时 ID，写进黑名单或名单拦不住任何人。极少数情况下游戏连临时 ID 都没给，这类人只计入人数并单独提示「另有 N 人无法列出」，不会让列表看起来像没人；
- **白名单没启用时**（预留位为 0），白名单页签会给出提示，其中的「房间设置」可以直接点进去改预留位——这个入口跟着要改的地方走，不需要先记住它在导航的哪一层；
- 显示「这次没能取到完整的在线玩家」表示查询没拿到结果（例如日志刷屏把查询结果冲掉了），**不代表房间里没人**，稍等自动刷新即可；
- 名字取自游戏进程与服务器日志，为空时显示「（未取名）」，对号入座请以玩家 ID 为准；名单里认不出名字的条目，面板会在打开页面时自动从日志里补一次。

## 20. 常见问题

### 玩家搜不到房间 / 连不上

按顺序排查：

1. 实例状态是否"运行中"，地上/洞穴分片是否都起来了（看控制台日志）；
2. 房间设置是否为公网联机且已保存 pds- 令牌；
3. **安全组是否放行了全部 UDP 端口**（主世界 3 个 + 洞穴 3 个，见第 4、13 章）——这是最常见原因；宿主机在 NAT 后面时，还要确认平台 / 路由器的端口转发覆盖了洞穴 3 个端口、且外部端口与内部一致（见 5.4 节）；
4. 是否设置了房间密码而玩家没输入；
5. 服务器负载是否过高导致广播超时（看监控台）；
6. 直连地址是否真的可用：命令下方提示里，来自"出站 IP 探测"的地址在本机 / 家用 NAT / 容器环境下往往不可直连，开着系统代理时还可能指向代理出口（见 5.2、5.3）。

### 面板打不开

curl -fsS http://127.0.0.1:9527/health 在服务器本机执行：本机通而外网不通 → 安全组没放行 9527/tcp；本机也不通 → 按关键词查 [INSTALL.md 的 FAQ](INSTALL.md#问题清单按报错关键词对照)。

### 镜像拉取失败（Docker 模式）

GHCR 不可达时优先使用 Release 离线镜像包，或在 panel.env 配置 GSH_IMAGE_MIRRORS。详见 [INSTALL.md · 路线 B（国内服务器）](INSTALL.md#路线-b国内服务器debian-12-离线镜像包全程) 与 [问题清单](INSTALL.md#问题清单按报错关键词对照)。

### SteamCMD 下载游戏慢

启用 --network cn 安装，或按 INSTALL.md 配置下载区域/代理。

### 开洞穴后内存吃紧

洞穴分片额外占用 1–2 GiB。4 GiB 机器建议先关洞穴或少开 Mod；档位建议见 [MEMORY.md](MEMORY.md)。

### 忘记密码

见 6.5 节。
